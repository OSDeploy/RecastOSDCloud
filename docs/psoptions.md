# PSDefaultParameterValues for OSDCloud

OSDCloud uses a **profile-based default system** to let you customise
`Invoke-WinPEStartup` parameter defaults without modifying the function call
in your startup script.

## How it works

```
Layer 1 (lowest precedence)
  <ModuleBase>\core\PSDefaultParameterValues.json
  Shipped with the module. Provides baseline defaults for every
  Invoke-WinPEStartup parameter.
        |
        v
USB Startup Profile (optional override)
  <DriveLetter>:\WinPEStartup\Profiles\*.json
  Scanned at startup on all connected drives. The selected profile
  overrides any matching Layer 1 defaults.
        |
        v
Explicit parameters (highest precedence)
  Parameters passed directly on the command line override all layers.
```

At module load time `Initialize-OSDCloudModule` calls
`Set-OSDCloudPSDefaultParameterValues`, which reads the module defaults file,
strips JSON comments (`//` and `/* */`), and merges the result into
`$global:PSDefaultParameterValues`. Keys use the format
`FunctionName:ParameterName`.

> **Important:** `Invoke-WinPEStartup` also reads profile JSON independently
> in its `begin` block and applies the values only for parameters that were
> not explicitly passed by the caller. This prevents pre-populated
> `$PSBoundParameters` from interfering with in-function default logic.

## Module default file location

```
<Get-OSDCloudModulePath>\core\PSDefaultParameterValues.json
```

Do not edit this file directly — your changes will be overwritten when the
module is updated. Use a startup profile to override defaults at deploy time.

## Full key reference

All keys prefixed with `Invoke-WinPEStartup:` that ship in `core/PSDefaultParameterValues.json`:

| Key | Type | Module Default | Description |
|---|---|---|---|
| `Invoke-WinPEStartup:SkipOnScreenKeyboard` | `bool` | `false` | Skip the on-screen keyboard check. |
| `Invoke-WinPEStartup:ShowPnpDevices` | `bool` | `false` | Show the PnP device hardware window. |
| `Invoke-WinPEStartup:ShowPnpErrors` | `bool` | `false` | Show the PnP device error window. |
| `Invoke-WinPEStartup:SkipWiFi` | `bool` | `false` | Skip the Wi-Fi startup step. |
| `Invoke-WinPEStartup:SkipIPConfig` | `bool` | `false` | Skip the IP configuration display window. |
| `Invoke-WinPEStartup:SkipUpdateOSDCloud` | `bool` | `false` | Skip the OSDCloud self-update step. |
| `Invoke-WinPEStartup:InstallModule` | `string[]` | `[]` | Additional modules to install during startup. |
| `Invoke-WinPEStartup:InvokeStartupCommand` | `string[]` | `[]` | Commands/URLs executed in the startup phase child process. |
| `Invoke-WinPEStartup:InvokeStartupCommandNoExit` | `bool` | `false` | Keep the startup-phase child window open after commands finish. |
| `Invoke-WinPEStartup:InvokeStartupCommandEA` | `string` | `"Continue"` | Error action for the startup-phase child process (`"Continue"` or `"Stop"`). |
| `Invoke-WinPEStartup:InvokeMainCommand` | `string[]` | `["Show-OSDCloudDeviceInfo","Deploy-OSDCloud"]` | Commands/URLs executed in the main phase child process. |
| `Invoke-WinPEStartup:InvokeMainCommandNoExit` | `bool` | `true` | Keep the main-phase child window open after commands finish. |
| `Invoke-WinPEStartup:InvokeMainCommandEA` | `string` | `"Continue"` | Error action for the main-phase child process. |
| `Invoke-WinPEStartup:InvokeShutdownCommand` | `string[]` | `[]` | Commands/URLs executed in the shutdown phase child process. |
| `Invoke-WinPEStartup:InvokeShutdownCommandNoExit` | `bool` | `false` | Keep the shutdown-phase child window open after commands finish. |
| `Invoke-WinPEStartup:InvokeShutdownCommandEA` | `string` | `"Continue"` | Error action for the shutdown-phase child process. |

## Overriding defaults

To override module defaults at deploy time, place a JSON profile at
`<DriveLetter>:\WinPEStartup\Profiles\*.json` on any USB drive connected
during WinPE startup. Profile keys can be written without the
`Invoke-WinPEStartup:` prefix (plain key) or with it (prefixed key) — both
are accepted.

The file supports `//` line comments and `/* */` block comments.

**Example: skip Wi-Fi, skip IP config, use a custom main command**

```json
{
    // Skip network display steps — this device is always wired
    "SkipWiFi": true,
    "SkipIPConfig": true,

    // Deploy using the 'latest' workflow channel
    "InvokeMainCommand": [
        "Show-OSDCloudDeviceInfo",
        "Deploy-OSDCloud -WorkflowName latest"
    ]
}
```

**Example: run a remote deployment script during startup**

```json
{
    "InvokeStartupCommand": [
        "https://raw.githubusercontent.com/myorg/winpe-config/main/setup.ps1"
    ],
    "InvokeMainCommand": [
        "https://raw.githubusercontent.com/myorg/winpe-config/main/deploy.ps1"
    ]
}
```

**Example: install extra modules**

```json
{
    "InstallModule": ["OSD", "OSDWorkspace"]
}
```

See [winpe-startup.md](winpe-startup.md#usb-startup-profiles) for how profiles
are discovered and selected at startup.

## Precedence summary

```
Explicit parameter  >  USB Startup Profile                   >  core\PSDefaultParameterValues.json
(highest)              (<Drive>:\WinPEStartup\Profiles\*.json)   (Layer 1 / lowest)
```
